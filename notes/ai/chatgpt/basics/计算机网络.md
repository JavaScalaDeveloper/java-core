# 一、网络分层

## TCP/IP 四层 vs OSI 七层

| TCP/IP | OSI | 协议例 |
|--------|-----|--------|
| 应用层 | 应用+表示+会话 | HTTP、DNS、TLS |
| 传输层 | 传输 | **TCP、UDP** |
| 网络层 | 网络 | IP、ICMP |
| 链路层 | 数据链路+物理 | 以太网、Wi-Fi |

## TCP vs UDP（必考）

| | TCP | UDP |
|--|-----|-----|
| 连接 | **面向连接** | 无连接 |
| 可靠 | 确认、重传、有序 | 不保证 |
| 速度 | 相对慢 | 快、开销小 |
| 场景 | HTTP、RPC、文件 | 视频、游戏、DNS、QUIC 内数据 |

# 二、输入 URL 后发生了什么？

```text
1. URL 解析（协议、域名、路径、参数）
2. DNS 解析 → IP（递归/迭代；缓存：浏览器→OS→LDNS）
3. 建立 TCP 连接（三次握手，HTTPS 再 TLS 握手）
4. 发 HTTP 请求
5. 服务器处理并响应
6. 浏览器解析 HTML/CSS/JS、渲染、可能继续请求资源
7. 连接关闭（四次挥手或 keep-alive 复用）
```

涉及：**DNS、TCP、TLS（HTTPS）、HTTP**。

# 三、TCP 可靠性

| 机制 | 作用 |
|------|------|
| **序列号 / ACK** | 有序、确认已收 |
| **超时重传** | 丢包重发 |
| **滑动窗口** | 流量控制（接收方能力） |
| **拥塞控制** | 慢开始、拥塞避免、快重传/快恢复 |
| **校验和** | 检错 |

# 四、三次握手 / 四次挥手

## 三次握手（建连）

```text
C → S: SYN, seq=x
S → C: SYN+ACK, seq=y, ack=x+1
C → S: ACK, ack=y+1
```

**为何三次？** 确认双方 **收发能力** 都 OK，并同步初始序列号。  
**两次不够：** 无法确认客户端收到了服务器的 SYN。

## 四次挥手（断连）

```text
C → S: FIN
S → C: ACK
S → C: FIN（等数据发完）
C → S: ACK
```

**为何四次？** TCP 全双工，双方各自关闭发送通道。  
**TIME_WAIT：** 主动关闭方等 2MSL，防最后 ACK 丢失导致对方重发 FIN 时无法正确响应。

## 常见追问

| 问题 | 答法 |
|------|------|
| SYN 洪水？ | 半连接队列满；SYN Cookie、限速 |
| 粘包/拆包？ | TCP 字节流无边界；应用层定长/长度头/分隔符 |
| keep-alive？ | HTTP 长连接复用 TCP；与 TCP keepalive 不同层 |

# 五、HTTP

## 状态码

| 类 | 含义 | 常考 |
|----|------|------|
| 2xx | 成功 | 200 OK |
| 3xx | 重定向 | 301 永久、302 临时、304 缓存 |
| 4xx | 客户端错 | 400、401、403、404 |
| **5xx** | **服务端错** | 见下 |

### 50x

| 码 | 含义 |
|----|------|
| **500** | 服务器内部未知错误 |
| **501** | 不支持该请求方法/功能 |
| **502** | 网关/代理收到上游 **无效响应** |
| **503** | 服务不可用（过载、维护） |
| **504** | 网关 **等待上游超时** |

**502 vs 504：** 502 上游回了坏响应；504 上游没及时回。

## HTTP/1.1 vs HTTP/2 vs HTTP/3

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
|--|----------|--------|--------|
| 连接 | 多连接或流水线有限 | **单连接多路复用** | 基于 **QUIC(UDP)** |
| 头部 | 明文重复 | **HPACK 压缩** | QPACK |
| 队头阻塞 | 有 | 连接级缓解 | 传输层进一步改善 |
| TLS | 可选 | 事实标配 | TLS1.3 集成 |

## GET vs POST（常问）

| | GET | POST |
|--|-----|------|
| 语义 | 查询 | 提交、改状态 |
| 参数 | URL Query | Body（常） |
| 缓存 | 可缓存 | 一般不 |
| 幂等 | 幂等 | 不一定 |

# 六、HTTPS 与 TLS 握手

## HTTP vs HTTPS

| | HTTP | HTTPS |
|--|------|-------|
| 安全 | 明文 | **TLS 加密** |
| 端口 | 80 | 443 |
| 证书 | 无 | 服务器证书验身份 |

HTTPS = HTTP + TLS（SSL 已统称 TLS）。

## TLS 握手（简化）

1. ClientHello（版本、套件、随机数）  
2. ServerHello + **证书** + 随机数  
3. 客户端验证书链（CA）  
4. 协商对称密钥（ECDHE 等）  
5. **Finished**，后续用 **对称密钥**（AES-GCM）加密 HTTP。

**混合加密：** 非对称换钥匙，对称运货。

# 七、对称加密与非对称加密（面试高频）

## 一句话区别

| | 对称加密 | 非对称加密 |
|--|----------|------------|
| 密钥 | **同一密钥** | **公钥 + 私钥** |
| 速度 | 快 | 慢 |
| 分发 | 难 | 公钥可公开 |
| 典型 | AES-GCM、ChaCha20 | RSA、ECC、SM2 |
| 用途 | 加密数据体 | 协商密钥、**数字签名** |

## 公钥 / 私钥

```text
保密：  公钥加密 → 私钥解密
签名：  私钥签名 → 公钥验证（常先 Hash）
```

## 数字签名 vs 加密

| | 加密 | 签名 |
|--|------|------|
| 目的 | 机密性 | 认证、防篡改、不可否认 |
| 操作 | 公钥加密或对称 | 私钥签、公钥验 |

## MAC vs 数字签名

- **HMAC**：共享密钥，双方都能伪造。  
- **数字签名**：仅私钥持有者可签。

## 国密

SM2 非对称、SM3 摘要、SM4 对称。

**30 秒收口：** HTTPS 证书 + 非对称协商会话密钥，AES-GCM 传数据；签名是私钥签公钥验。

# 八、场景题

## 上传/下载为何先慢后快？

- TCP **慢启动**：拥塞窗口从小变大。  
- 连接建立、TLS 握手耗时。  
- 接收方滑动窗口逐渐放开。  
- 丢包重传阶段会波动。  
- 客户端/服务端缓冲、限速策略。

## CDN 原理（简述）

边缘节点缓存静态资源；DNS 解析到就近节点；源站回源；减轻延迟与源站压力。

## WebSocket

全双工长连接；握手走 HTTP Upgrade；适合推送、实时协作。

## Cookie / Session / Token

| | Cookie | Session | Token（JWT） |
|--|--------|---------|--------------|
| 存哪 | 浏览器 | 服务端内存/Redis | 客户端持 Token，服务端验签 |
| 跨域 | 受限 | 服务端状态 | 无状态 API 常见 |
