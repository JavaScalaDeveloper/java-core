# MBTI：INTJ（建筑师型）

> 个人类型：**INTJ** — Introverted / Intuitive / Thinking / Judging  
> 常用别名：**建筑师**、**策略家**、**专家型**

---

## 一句话画像

内向、以 **长远目标与系统逻辑** 驱动；习惯独立规划，用理性做决策，重视效率与正确性，对低效和模糊容忍度低。

---

## 四个维度

| 维度 | 含义（INTJ 侧） |
|------|-----------------|
| **I 内向** | 独处恢复能量；深度思考优于频繁社交 |
| **N 直觉** | 关注模式、架构、未来可能，而非仅眼前细节 |
| **T 思考** | 决策优先逻辑与客观标准，而非人情和氛围 |
| **J 判断** | 喜欢计划、截止与闭环；讨厌长期悬而未决 |

---

## 核心优势（面试/工作可讲）

| 优势 | 表现 |
|------|------|
| **战略思维** | 能拆复杂系统、定技术路线、看 3～5 步后的演进 |
| **独立攻坚** | 单兵深挖问题、读源码、啃难题 |
| **标准与质量** | 重视设计一致性、边界条件、可维护性 |
| **学习驱动** | 新技术栈、原理类知识吸收快 |
| **果断** | 方案权衡后敢拍板，推进落地 |

---

## 常见短板（自知 + 改进话术）

| 短板 | 改进方向 |
|------|----------|
| 表达偏简、默认别人「应该懂」 | 文档化、评审会主动对齐、关键结论写进 Wiki |
| 对低效/不合理流程不耐烦 | 用数据说话，提改进方案而非只批评 |
| 社交能量有限 | 必要沟通做足（站会、方案评审），非必要聚会选择性参与 |
| 完美主义拖进度 | MVP 先交付，迭代优化；区分「必须对」和「可以后改」 |

**面试收口：** INTJ 不是「不合群」，而是 **用结果和逻辑建立信任**；在团队里适合架构、核心模块、复杂问题 owner。

---

## 适合的方向（Java 开发语境）

| 更适合 | 需刻意补位 |
|--------|------------|
| 后端架构、核心服务、性能与稳定性 | 高频跨部门扯皮、纯销售型对外 |
| 技术方案设计、重构、中间件 | 强表演型汇报（可练 PPT + 结构化表达） |
| 代码质量、规范、Review | 24h on-call 轮值（需排班与文档传承） |

---

## 与 PDP 动物类型对照（用人单位常同时用）

| PDP 类型 | 与 INTJ 关系 |
|----------|--------------|
| **猫头鹰**（精确、分析） | **高度一致** — 逻辑、严谨、重正确 |
| **老虎**（决断、目标） | **较一致** — 独立、拍板、要结果 |
| **考拉**（温和、稳定） | 部分 — 不一定外向暖，但能 **稳定交付、少冲突** |
| **孔雀**（表现、社交） | **通常偏低** — 不必强行装「话痨」，但 **沟通清晰** 即可 |

你已对外说明是 INTJ，后续 PDP 等测评宜 **猫头鹰/老虎偏高、孔雀偏低**，与 INTJ 叙事一致（详见 `PDP测试表填写指南.md`）。

## 面试 30 秒自我介绍（INTJ 版）

「我是 INTJ，习惯先想清架构和边界再动手，擅长 Java 后端和复杂问题拆解。性格偏内向，但需求评审、Code Review 和文档我会主动对齐，保证团队信息透明。优势是独立学习和长期技术规划，也在刻意加强跨团队沟通和按时交付，避免过度追求完美影响进度。」
