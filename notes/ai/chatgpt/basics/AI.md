# AI 面试题

覆盖应用开发常问：LLM 基础、Function Calling、Agent、Skills、MCP、RAG、评测与上线。偏工程落地，少谈训练细节。

---

## 知识地图

```text
用户问题
  →（可选）RAG 检索知识
  → LLM（可 Function Calling / 结构化输出）
  →（可选）Agent Loop：规划 → 调工具(MCP/API) → 观察 → 再推理
  → Skills / Prompt / 上下文工程 约束行为
  → 网关：限流、路由、兜底、观测
```

| 概念 | 一句话 |
|------|--------|
| LLM | 大语言模型，按概率续写 Token |
| Prompt / 上下文工程 | 把约束、工具、记忆组织进上下文 |
| Function Calling | 模型选工具并产出结构化参数 |
| Agent | 多步决策：推理 + 行动 + 观察循环 |
| Skills | 可复用的能力包（流程/脚本/模板） |
| MCP | 工具/资源接入的开放协议 |
| RAG | 先检索再生成，补私有知识 |

## LLM 基础常问

### Token、上下文窗口、采样参数

- **Token**：模型读写的基本单位（不等同汉字个数）。
- **上下文窗口**：单次可塞进的 Token 上限；超了要截断、摘要或外置记忆。
- **temperature**：越高越随机；事实问答宜低。
- **top_p / top_k**：核采样，限制候选 Token。
- **max_tokens**：限制生成长度，防跑飞与控成本。

### 幻觉是什么？怎么缓解？

模型生成流畅但错误的内容。缓解：RAG 接地、要求引用出处、结构化输出校验、工具查真源、降低温度、人工/自动评测、拒答策略。

### 微调、RAG、Prompt 怎么选？

| 手段 | 适合 |
|------|------|
| Prompt / 少样本 | 格式、语气、简单规则 |
| RAG | 私域知识、常更新文档 |
| 微调 | 稳定风格/领域用语、特定格式，成本高 |
| 工具调用 | 要实时数据或执行动作 |

优先：**能 Prompt/RAG 解决就不要上微调**。

## Function Calling / 工具调用

### 解决什么问题？

让模型在需要时 **调用外部 API/函数**（查库、下单、搜文档），而不是编造结果。

### 基本流程

1. 把工具 schema（名称、描述、参数 JSON Schema）发给模型  
2. 模型返回 `tool_call`（函数名 + 参数）  
3. 业务执行工具，把结果塞回对话  
4. 模型基于结果继续回答或再调工具  

### 和普通 Prompt 出 JSON 的区别？

Function Calling 有协议与校验，模型被训练成更稳地选工具；仍要 **服务端校验参数**（类型、枚举、权限），不能信模型。

### 结构化输出

用 JSON Schema / 受限解码保证字段完整；失败要重试或降级。业务系统应校验后再落库。

## AI Agent

### 什么是 Agent？和 Chat、Workflow 区别？

| | Chatbot | Workflow | Agent |
|--|---------|----------|-------|
| 路径 | 单轮/多轮问答 | 预定义流程图 | 按中间结果动态选下一步 |
| 工具 | 可有可无 | 节点写死 | 循环中自主选工具 |
| 适合 | FAQ、陪聊 | 审批、固定 ETL | 排查、调研、多步任务 |

**Agent ≈ 模型 + 工具 + 记忆 + 循环（感知→思考→行动）**。

### Agent Loop / ReAct

```text
while not done:
  Thought（可选）
  Action = 选工具 + 参数
  Observation = 工具结果
  判断结束或继续
```

要有：**最大步数、超时、幂等、人工确认点（高风险操作）**。

### Plan-and-Execute

先规划步骤再执行；适合长任务。计划也可随观察修正（Replan）。

### Agent 常见失败

- 工具选错 / 参数幻觉  
- 死循环、重复调用  
- 上下文爆掉（要摘要、记忆分层）  
- 权限过大（任意 Shell/SQL）  

对策：白名单工具、schema 校验、步数限制、轨迹日志、评测集。

### AI Agent 完整开发流程（工程向）

从 0 到上线，可按下面阶段推进；面试按「目标 → 能力 → 闭环 → 治理」讲即可。

```text
1. 场景与边界
2. 能力设计（工具 / 知识 / 记忆）
3. 编排与 Prompt
4. 实现（代码 Agent 或平台配置）
5. 评测与护栏
6. 上线观测与迭代
```

**1. 场景与边界**

- 明确任务：问答 / 查数 / 办工单 / 写代码辅助 / 巡检……  
- 成功标准：正确率、时延、人工介入率、能否闭环。  
- 非目标：不做什么（禁止改生产、禁止转账等）。  
- 用户与权限：谁能用、能碰哪些系统。

**2. 能力设计**

| 能力 | 内容 |
|------|------|
| 工具 | API / MCP / 内部 RPC；每个工具：描述、参数 schema、权限、是否需人工确认 |
| 知识 | 要不要 RAG；文档范围、更新频率、权限过滤 |
| 记忆 | 会话短记忆；是否要用户偏好/长期记忆 |
| 模型 | 主模型 + 便宜模型做路由/摘要；温度与超时 |

**3. 编排与 Prompt**

- 选范式：单次 Function Calling / ReAct 循环 / Plan-and-Execute / 固定 Workflow+局部 Agent。  
- 系统提示：角色、工具使用规则、拒答与升级人工。  
- 结束条件：目标达成、用户确认、步数/超时用尽。

**4. 实现两种路径**

- **代码开发**：用 LangGraph / Spring AI / 自研 Loop 调模型与工具；适合强定制、深集成、要进现有微服务。  
- **平台配置（低代码/零代码）**：见下一节；适合快速试点、运营可改流程。

**5. 评测与护栏**

- Golden 集：典型问法 + 期望工具轨迹/答案要点。  
- 护栏：最大步数、工具白名单、参数校验、敏感词、高风险二次确认。  
- 轨迹日志：Thought/Action/Observation 可回放，便于归因。

**6. 上线与迭代**

- 灰度、限流、降级（Agent 挂了走 FAQ/人工）。  
- 看：工具成功率、循环步数、成本、点踩、人工接管率。  
- 坏例回流改 Prompt/工具描述/知识库，而不是只换更大模型。

**交付物清单（加分）：** 场景说明书、工具目录、Prompt/版本、评测集、权限矩阵、Runbook（超时/幻觉/工具失败怎么处理）。

### 不写代码（仅页面配置）怎么配置和使用 AI Agent？

很多产品把 Agent 收成 **可视化编排 + 表单配置**：运营/产品在控制台完成，研发只提供 API/MCP 与账号权限。

#### 典型零代码/低代码平台

| 类型 | 代表（举例） | 你在页面上配什么 |
|------|--------------|------------------|
| Agent 应用平台 | Coze、Dify、FastGPT、扣子类 | 人设、插件/工具、知识库、开场白、变量 |
| 对话式 GPTs | ChatGPT GPT Builder 等 | 指令、上传知识、勾选 Actions |
| 自动化编排 | n8n、Zapier、Make | 触发器 → LLM 节点 → HTTP/业务节点 |
| 云厂商 Agent | 各云「智能体/应用编排」控制台 | 模型、插件市场、工作流画布 |
| 企业 IM 机器人 | 飞书/钉钉/企微开放平台机器人 | 事件订阅、指令菜单、连接审批/文档 |

（具体产品名随公司选型变化；面试强调 **「配置项」而不是背品牌**。）

#### 页面上一般怎么配（通用步骤）

```text
创建 Agent → 写人设/系统指令
  → 挂知识库（上传文档 / 绑已有库）
  → 开工具：官方插件 or 填 OpenAPI/MCP/Webhook
  →（可选）拖拽工作流：条件分支、人工节点、代码节点（可不用）
  → 设变量、开场白、推荐问、安全策略
  → 发布：Web / API / 嵌入网站 / 绑 IM
  → 对话测试 → 看调用轨迹 → 改指令或工具描述
```

**1. 人设与指令（System Prompt）**  
页面大文本框：角色、语气、必须/禁止、何时调工具、答不上来怎么办。

**2. 知识库（无代码 RAG）**  
上传 PDF/Markdown/网页；平台自动切分、向量化；可配「仅根据知识库回答」。

**3. 工具 / 插件（关键）**  

- 市场一键安装（天气、搜索、日历…）。  
- **自定义**：粘贴 OpenAPI Schema 或填 URL + Header；把「查订单」「创建工单」做成按钮式工具。  
- 有的平台支持填 **MCP Server 地址**，仍可不写业务代码（工具服务已由别人提供）。

**4. 工作流画布（半 Agent）**  
拖节点：LLM → 调 API → 条件判断 → 结束。路径偏固定，稳定性高；复杂处再嵌「Agent 节点」让模型选分支。

**5. 发布与使用**  

- 体验页直接聊；或生成 API Key 给前端/后端调。  
- 发布到飞书/钉钉/企微/网页挂件。  
- 权限：访客 / 登录用户；知识库按租户隔离看平台能力。

**6. 运维仍在控制台**  
看会话日志、工具调用是否失败、改 Prompt 热更新、回滚版本——通常 **仍不用发版写代码**。

#### 零代码能做 / 不能做

| 适合页面配置 | 往往仍要研发 |
|--------------|--------------|
| FAQ + 知识库问答 | 复杂权限与数据隔离深嵌现有中台 |
| 调已有 HTTP 接口办简单事 | 新业务 API、事务一致性 |
| 原型验证、运营可改话术 | 毫秒级延迟、强可控编排 |
| IM 机器人客服/助手 | 任意 Shell、生产库写入（也不该给零代码乱开） |

#### 口述对比：配置 Agent vs 开发 Agent

- **只配页面**：快、运营可改；能力受平台插件与已有 API 限制。  
- **写代码**：灵活、易进 CI/微服务与细粒度鉴权；成本高、改指令也常要发版（除非配置外置）。  
- 实践：**先用 Dify/Coze 等验证场景 → 核心链路再收编进自研 Agent**；工具层尽量沉淀为 MCP/OpenAPI，两边都能挂。

#### 30 秒收口

“Agent 开发流程是：定场景边界 → 设计工具/知识/记忆 → 选 Loop 或工作流 → 实现（代码或平台）→ 评测护栏 → 观测迭代。若不允许写业务代码，就在 Agent 平台里配人设、知识库、OpenAPI/MCP 工具和工作流，发布到 Web 或 IM；研发只提供安全的只读/白名单接口。高风险动作必须人工确认，不能只靠页面勾选就放开生产写权限。”

## Skills

### Skills 是什么？和 Prompt、MCP 差在哪？

| | Prompt | Skills | MCP |
|--|--------|--------|-----|
| 本质 | 一段指示文本 | 可复用能力包（说明+脚本+资源+流程） | 工具/资源接入协议 |
| 复用 | 复制粘贴 | 安装/加载到 Agent | 标准连接外部系统 |
| 例子 | 「用中文回答」 | 「按公司规范写 PR / 跑巡检」 | 连 GitHub、浏览器、DB |

一句话：**Prompt 是话术；Skills 是打包好的做事方式；MCP 是插工具的插座。**

### 为什么需要 Skills？

把重复的最佳实践（检查清单、命令、模板）固化，减少每次重新「教」模型；便于团队共享与版本管理。

## MCP（Model Context Protocol）

### 解决什么问题？

工具接入碎片化：以前每个产品私有插件协议。MCP 提供 **统一方式** 让宿主（IDE/Agent）连接 MCP Server，发现并调用 **Tools / Resources / Prompts**。

### 和 Function Calling 关系？

- Function Calling：模型侧「如何表达要调哪个函数」  
- MCP：工程侧「工具怎么注册、发现、鉴权、传输」  

可组合：MCP 工具 → 转成 Function schema → 交给模型 Function Calling。

### 安全注意

MCP Server 能读文件、跑命令则风险高：权限最小化、沙箱、用户确认、审计日志、供应链可信。

## RAG

### 什么是 RAG？为什么需要？

**Retrieval-Augmented Generation**：先检索相关文档片段，再塞进 Prompt 让模型生成。  
解决：私有知识、知识更新、降低幻觉（有依据时）。

### 经典链路

```text
文档 → 解析清洗 → 切分(Chunk) → Embedding → 向量库
用户问题 →（可选改写）→ 检索 Top-K →（可选重排）→ 拼上下文 → LLM 生成
```

### 切分怎么做？

按标题/段落语义切；有重叠（overlap）；表格/代码特殊处理；太大噪声多，太碎丢失上下文。

### 检索优化

- 混合检索：向量 + 关键词（BM25）  
- Query 改写 / 多路召回  
- **Rerank** 精排  
- 元数据过滤（权限、时间、租户）  
- GraphRAG：实体关系，适多跳问题  

### RAG 答非所问先查什么？

先查 **召回**：切分、Embedding、Top-K、过滤、权限是否把证据滤掉；再查重排与 Prompt；最后才怪模型不够大。

### 知识更新

增量upsert、版本号、软删除、定期全量重建；避免旧切片残留。

## 上下文工程（Context Engineering）

比「写妙 Prompt」更完整：系统指令、工具定义、检索结果、对话摘要、长期记忆、中间状态如何 **选、压、排** 进有限窗口。

原则：相关、新鲜、结构清晰、引用可追溯；无关信息会抢 Token 并干扰。

---

## 评测与上线

### 怎么评？

- **Golden Set**：固定问答 + 期望要点  
- 人工抽检 + LLM-as-Judge（要校准）  
- 线上：点赞点踩、拦截率、工具成功率、延迟、成本  

### 生产还要什么？

网关（多模型路由、降级）、超时重试、限流、内容安全、鉴权、Trace、Prompt/版本管理、成本看板。

只调 API 不够；要当 **分布式服务** 做。

## 对比速记（高频口试题）

**Agent vs RAG？**  
RAG 补知识；Agent 补「多步行动」。常组合：Agent 在循环里调用检索工具。

**Function Calling vs Agent？**  
前者是一次/少数次工具调用能力；后者是带状态的多步决策框架（通常包含前者）。

**MCP vs 插件私有协议？**  
MCP 标准化发现与调用，降低「每个宿主写一套适配」。

**微调 vs RAG？**  
常更新事实 → RAG；稳定风格/格式 → 可考虑微调。

## 口述题：设计一个公司内部 AI 助手

答出层次即可：

1. 入口：Web/IM + 身份鉴权  
2. 意图：问答 / 查系统 / 执行操作  
3. 知识：权限内 RAG  
4. 行动：白名单工具（MCP/API），高风险人工确认  
5. 记忆：会话短记忆 + 可选长期偏好  
6. 治理：审计、限流、评测、成本、兜底话术

## 一页速记

| 主题 | 要点 |
|------|------|
| Function Calling | schema → 调工具 → 回灌结果；服务端校验 |
| Agent | Loop + 工具 + 限制步数/权限；流程：场景→能力→编排→实现→评测→上线 |
| Agent 零代码 | 平台配人设/知识库/OpenAPI·MCP/工作流并发布；高风险须人工确认 |
| Skills | 可复用能力包，不等于一句 Prompt |
| MCP | 工具接入协议；注意安全 |
| RAG | 切分/向量/召回/重排；先查召回 |
| 上线 | 评测 + 网关 + 观测 + 安全 |
