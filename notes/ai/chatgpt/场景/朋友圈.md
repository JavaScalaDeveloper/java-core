# 场景面试：朋友圈（Moments）完整流程设计

> 典型特征：**强隐私**（好友可见）、**双向好友**、**时间序 Feed**、**读多写少**、**互动轻量**（赞/评）。  
> 与微博差异：无公开时间线给陌生人；与大 V 场景差异：单人好友上限 ~5000，但 **仍可能走推拉混合**。

---

## 1. 产品能力清单

| 能力 | 说明 |
|------|------|
| **发送** | 文字/图/视频/链接；可选位置、@、可见范围 |
| **阅读** | 朋友圈时间线；个人相册；单条详情 |
| **互动** | 点赞、评论（楼中楼）、删除自己的赞评 |
| **隐私** | 谁可以看/不可看；拉黑；仅聊天的好友 |
| **其它** | 删动态、设为私密、三天可见、提醒谁看 |

---

## 2. 核心数据模型

```text
moment          动态主表
moment_media    媒体（url, type, sort）
moment_privacy  可见性规则（可选 JSON / 规则表）
like            moment_id, user_id, ts
comment         moment_id, user_id, reply_to, content, ts
friendship      user_a, user_b, status（双向好友）
block           blocker, blocked
user_moment_setting  三天可见、不让他看、不看他 等
```

| moment 关键字段 | 说明 |
|-----------------|------|
| author_id | 发布者 |
| content | 文本 |
| visibility | PUBLIC / PRIVATE / PARTIAL / EXCLUDE |
| created_at | 排序 |
| status | NORMAL / DELETED / AUDIT |

---

## 3. 好友关系与可见性（读之前必算）

### 3.1 双向好友

```text
A 看 B 的朋友圈 ⟺ friendship(A,B)=ACCEPTED
且 B 未 block A
且 A 未「不看他(B)」
且 B 未「不让他看(A)」
```

**维护**：

- `friend:list:{userId}` Redis Set（双向）  
- 变更好友/拉黑/隐私设置 → **删双方 Feed 缓存**

### 3.2 单条可见性

| 类型 | 判断 |
|------|------|
| 公开（好友） | 在好友集内即可 |
| 部分可见 | user_id IN allow_list |
| 不给谁看 | user_id NOT IN deny_list |
| 私密 | 仅 author 自己相册 |

**读 Feed 时**：拉候选 moment → **逐条或批量规则过滤**（好友关系已保证大部分）。

## 4. 发送流程（完整）

```text
┌──────────┐
│ 客户端    │
└────┬─────┘
     │ 1. 选图/视频 → STS 直传 OSS（见 文件上传.md）
     │ 2. POST /moment/publish { content, mediaIds[], visibility, atUserIds[] }
     ▼
┌──────────────┐
│  动态服务     │
└──────┬───────┘
       │ 3. 鉴权、敏感词、频控（防刷）
       │ 4. 本地事务：
       │      INSERT moment
       │      INSERT moment_media
       │      INSERT moment_privacy（若有）
       │ 5. 写 author 的 outbox：timeline:{authorId} ZADD postId ts
       │ 6. 发 MQ moment_published { momentId, authorId, friendCount, ts }
       │ 7. 返回 momentId
       ▼
┌──────────────┐
│  Fan-out     │  （异步，见 §5）
└──────────────┘
       │
       ├→ 搜索/审核 MQ（可选）
       └→ @ 提醒通知（给 at 的人，非全员 Push）
```

### 4.1 发送侧事务

```sql
BEGIN;
  INSERT INTO moment (...) VALUES (...);
  INSERT INTO moment_media (...) VALUES (...);
  -- 可见性规则表
COMMIT;
```

**媒体**：上传与发布分离；发布时校验 media 归属 author。

### 4.2 频控与安全

- 单日条数上限；视频大小/时长  
- 敏感词 + 机审 → `AUDIT` 态仅自己可见  
- 审核通过 → MQ 触发 fan-out（或先发后审产品则先 fan-out）

## 5. Fan-out：好友动态怎么进「我的 Feed」？

### 5.1 好友规模

微信好友上限约 **5000**；比百万粉小得多，**写扩散可行但要用异步**。

| 策略 | 适用 |
|------|------|
| **推（写扩散）** | 好友 < 2k～5k；异步 ZADD `inbox:{friendId}` |
| **拉** | 好友极多或超级节点（少见） |
| **混合** | 常在线好友推；冷门好友读时补拉 |

### 5.2 推荐：异步推 inbox

```text
moment_published 消费：
  1. 查 author 的好友列表（分页，每页 500）
  2. 对每个好友 friendId：
       若通过可见性规则（exclude/block/不让他看）
         ZADD inbox:{friendId} ts momentId
  3. 幂等：(momentId, friendId) 去重
  4. 可选：给「常互动好友」发 Push / 红点信令
```

**发帖同步路径不等待** fan-out 完成。

### 5.3 超级节点（可选）

若存在「好友 5000 且全活跃」：

- 仍 **MQ 分批 fan-out**  
- 或对该用户标记 **bigFriend**，好友读时 **拉** `timeline:{authorId}` 合并（同 [大V发通知.md](./大V发通知.md)）

## 6. 阅读流程（完整）

### 6.1 刷朋友圈首页

```text
GET /moments/feed?cursor={lastTs}&limit=10

1. 鉴权 userId
2. ZREVRANGEBYSCORE inbox:{userId} cursor  → momentId 列表
   （miss 则 DB 或重建 inbox）
3. 批量 MGET moment:{id} 详情 + 作者信息
4. 二次过滤（删帖、拉黑后、隐私变更、三天可见过期）
5. 批量查 like/comment 摘要（前 3 赞、评论数）
6. 组装 DTO 返回 + nextCursor
```

### 6.2 个人相册（某人全部动态）

```text
GET /moments/user/{authorId}?cursor=

- 若 viewer == author → 查 author_timeline 全量（含私密）
- 若 viewer 是好友 → timeline + 隐私规则过滤
- 非好友 → 403 或空（朋友圈不对陌生人开放）
```

### 6.3 单条详情

```text
GET /moments/{id}
  校验可见性 → 返回全文 + 赞列表 + 评论树
```

### 6.4 未读 / 红点

```text
方案 A：inbox 最大 ts > user:last_read_moment_ts → 有更新
方案 B：客户端记住上次 cursor，服务端比较
不推荐：每条 moment 给好友 INCR 未读（写放大）
```

### 6.5 三天 / 半年可见

- 读时过滤：`created_at > now() - interval`  
- 或定时任务标记 `expired` 并从 inbox **ZREM**  
- 相册页同步过滤

## 7. 互动流程

### 7.1 点赞

```text
POST /moments/{id}/like

1. 校验可见性
2. INSERT like UNIQUE(moment_id, user_id)  -- 幂等
3. Redis INCR like:count:{momentId}；SADD like:users:{momentId} userId（可选）
4. 删 moment 详情缓存
5. MQ moment_liked → 通知作者（Push/站内，可合并）
```

取消赞：`DELETE` + 删记录 + DECR。

### 7.2 评论

```text
POST /moments/{id}/comment { content, replyToCommentId? }

1. 校验可见性
2. INSERT comment
3. INCR comment:count
4. 通知被 @ / 作者 / 被回复者（MQ，非同步）
5. 评论列表分页：按 ts 或楼中楼树
```

### 7.3 删除动态

```text
作者 DELETE moment
  → status=DELETED
  → MQ fanout_delete：从所有好友 inbox ZREM momentId
  → 删缓存
```

## 8. 隐私与拉黑（变更时）

| 操作 | 影响 |
|------|------|
| 删除好友 | 可选从 inbox 清理双方相关 moment（或读时过滤） |
| 拉黑 | 读时不可见；inbox 异步清理 |
| 「不看他」 | 读 Feed 跳过该 author；可不删 inbox |
| 「不让他看」 | fan-out 时跳过该好友；历史可读产品决定 |

**隐私变更**：异步任务扫 author 历史 moment 重算 fan-out（ heavy，低峰跑）。

## 10. 事务 / 分布式事务

| 操作 | 事务 |
|------|------|
| 发动态 | moment 表单库 **本地事务** |
| Fan-out | **无**；MQ 最终一致 + 幂等 |
| 点赞/评论 | 互动表单库本地事务 |
| 通知 | MQ **最终一致** |
| 跨服务（动态+通知） | **不用 Seata** |

---

## 11. 缓存策略

| 数据 | 策略 |
|------|------|
| moment 详情 | `moment:{id}`，赞/评变更删 |
| inbox | `inbox:{userId}` ZSet，fan-out 写 |
| 好友列表 | `friend:{userId}` Set |
| Feed 聚合页 | **短 TTL 难做**（个性化强）；靠 inbox + 详情缓存 |
| 赞数/评数 | Redis 计数 + 异步落库 |

**一致性**：写 DB → 删缓存；inbox 与 DB 以 **MQ 补偿** 对齐。

---

## 12. 读写分离

| 操作 | 路由 |
|------|------|
| 发布、赞、评 | **主库** |
| Feed 拉取、相册浏览 | **Redis inbox 优先**；miss 读 **从库** |
| 刚发布后作者看自己 | **读主** 或 读 author_timeline（已写主） |

主从延迟：好友可能晚 1～2 秒刷到新动态（通常可接受）。

---

## 13. 高并发

| 点 | 手段 |
|----|------|
| 刷 Feed | inbox ZSet O(logN)；批量 mget |
| 热点 moment（全民围观极少） | 本地缓存 + CDN 图 |
| 晚高峰全员刷 | 接入层限流；Redis Cluster |
| Fan-out | MQ 分区按 authorId；consumer 水平扩展 |
| 点赞 | Redis 抗写；异步落库 |

---

## 14. 分页与性能

- **禁止**深分页 `OFFSET 100000`  
- 用 **cursor（ts, momentId）** 游标  
- inbox ZREVRANGEBYSCORE 天然支持

---

## 15. 与「大 V 100 万粉」对比（面试常问）

| | 朋友圈 | 微博大 V |
|--|--------|----------|
| 关系 | **双向好友** | 单向关注 |
| 受众规模 | ≤5000/人 | 百万级 |
| Fan-out | **可异步推 inbox** | **必须拉** |
| 隐私 | 强规则 | 公开为主 |
| 陌生人 | 不可见 | 可见时间线 |

---

## 16. 异常与补偿

| 异常 | 处理 |
|------|------|
| Fan-out 一半失败 | MQ 重试；幂等 ZADD |
| 发帖成功未 fan-out | 补偿任务扫 `fanout_status=PENDING` |
| 删帖后仍出现在 Feed | 读时过滤 + 异步 ZREM inbox |
| 审核驳回 | 状态变更 + 从 inbox 移除 |

---

## 17. 面试追问

| 追问 | 要点 |
|------|------|
| 为什么用 inbox？ | 读 Feed O(自己的条数)，不用每次聚合所有好友 |
| 好友 5000 写扩散行吗？ | **异步 MQ** 分批 ZADD；发帖接口不阻塞 |
| 隐私怎么保证？ | Fan-out 过滤 + 读时二次校验 |
| 三天可见怎么实现？ | 读过滤 + 定时从 inbox 清理 |
| @ 某人？ | 单独通知；不必全员 fan-out 差异 |

---

## 18. 30 秒收口

「朋友圈：**双向好友 + 强隐私**。发动态 **本地事务写 moment**，**MQ 异步 fan-out** 到好友 `inbox` ZSet；读 Feed **游标拉 inbox** + 批量详情 + 隐私/过期过滤。赞评独立服务、**Redis 计数** + MQ 通知。不用分布式事务；缓存写后删；写主读从 + inbox 抗读。」
