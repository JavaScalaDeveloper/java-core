# 场景面试：退款 / 逆向

---

## 1. 流程

```text
用户申请 → 审核（可选）→ 创建 refund 单 → 调渠道退款 API
  → 退款回调（幂等）→ 更新 order/refund 状态
  → 库存回滚、券退回、积分扣回（MQ 最终一致）
```

---

## 2. 状态机

```text
refund: INIT → PROCESSING → SUCCESS / FAILED
order:  PAID → REFUNDING → REFUNDED（部分退保持 PAID + 子状态）
```

---

## 3. 事务与一致性

- 退款服务：**本地事务** 建 refund + Outbox  
- 渠道退款 **异步**；以回调为准  
- **不能**先改订单再调渠道失败无补偿 → 状态机严格推进  
- 库存/积分：**MQ 幂等** 回滚

---

## 4. 部分退 / 多次退

- 累计退款金额 ≤ 实付  
- 每次退款独立 `refund_no` 幂等  
- 分摊：商品行维度退库存

---

## 5. 幂等

- 渠道退款回调同支付  
- `refund_no` 唯一；重复回调直接 success

---

## 6. 缓存 / 读写分离

- 写主；退款列表读从  
- 删订单/商品详情缓存

---

## 7. 高并发

- 大促后退款峰值：MQ 削峰；渠道 API 限流排队

**收口**：「独立 refund 状态机；渠道异步+幂等；订单/库存/券 MQ 补偿。」
