# 场景面试：下单

> 电商核心链路：**校验 → 算价 → 锁/预占库存 → 写订单 → 异步下游**。  
> 考察：本地事务、分布式事务边界、缓存、读写分离、高并发、幂等、MQ。

---

## 1. 场景与核心挑战

| 挑战 | 说明 |
|------|------|
| **一致性** | 订单、库存、优惠券、积分不能各写各的乱套 |
| **超卖** | 高并发下库存不能减成负数 |
| **重复下单** | 用户连点、网络重试、MQ 重复 |
| **性能** | 大促 QPS 高；不能所有逻辑同步串行 |
| **读多写少** | 商品读缓存；订单写主库、列表读从库 |
| **主从延迟** | 下单后立即查列表可能看不到 |

---

## 2. 业务流程（标准版）

```text
1. 客户端带 submitToken（防重）请求下单
2. 网关鉴权、限流（Sentinel / 用户维度 QPS）
3. 订单服务：
   a. 校验 submitToken（Redis SETNX 或 DB 唯一约束）
   b. 读商品/价格（缓存 + 降级；价格以服务端为准）
   c. 校验库存（Redis 预检 or 直接调库存服务）
   d. 算价：商品金额 - 券 - 活动 + 运费
   e. 预占库存（库存服务）
   f. 本地事务写：order + order_item + 券核销记录（同库）
   g. 发 MQ：order_created（Outbox 或 RocketMQ 半消息）
4. 返回 orderId + 待支付
5. 异步：积分、通知、搜索索引、BI、风控
6. 支付超时 → 关单 + 释放库存（延迟消息 / 定时任务）
```

---

## 3. 架构分层

```text
客户端 → API Gateway → 订单服务
                          ├→ 商品服务（读缓存）
                          ├→ 库存服务（预占/释放）
                          ├→ 促销/券服务
                          └→ 支付服务（创建支付单，可同步或异步）
         MySQL（订单库）  Redis（token/缓存）  MQ（下游）
```

| 服务 | 职责 | 一致性 |
|------|------|--------|
| 订单 | 订单主数据、状态机 | 本地事务 |
| 库存 | 可售库存、预占、确认、释放 | 强一致（DB+锁） |
| 促销/券 | 规则、核销 | 核销与订单同事务或 TCC |
| 支付 | 支付单 | 独立；回调驱动订单 |

---

## 4. 事务怎么设计？

### 4.1 能放在一个库里的（优先本地事务）

同一 MySQL 实例 / 同一分库：

```sql
BEGIN;
  INSERT INTO `order` ...;
  INSERT INTO order_item ...;
  UPDATE coupon_user SET status=USED WHERE ...;  -- 券在本库
COMMIT;
```

**原则**：订单头、明细、本库内的券/活动记录 → **一个本地事务**。

### 4.2 跨服务（库存、券在别的库）

| 方案 | 适用 | 说明 |
|------|------|------|
| **先预占库存再写单（推荐）** | 常规电商 | 库存 Try 成功再写订单；失败则不写单 |
| **Seata AT** | 多库、团队熟悉 Seata | 短事务；避免长链路 |
| **TCC** | 强一致、资金级 | Try 预占库存/券，Confirm 写单 |
| **Saga** | 长履约 | 下单→仓→配，逐步补偿 |
| **最终一致** | 积分、通知 | MQ + 幂等，不参与下单同步路径 |

**推荐口述顺序**：

```text
同步路径：预占库存（库存服务本地事务）→ 订单服务本地事务写单
         → 失败则调库存释放（补偿）
异步路径：MQ 通知积分/搜索/短信
```

**不要**在下单同步链路里开 `@GlobalTransactional` 包五六个 RPC，除非业务明确要求且压测过。

### 4.3 与支付的分界

- 下单阶段：**创建待支付订单**，不扣款。  
- 支付成功回调：**更新订单已支付** + **库存确认扣减**（预占→实扣）。  
- 两阶段库存：预占（下单）→ 确认（支付成功）→ 释放（关单/超时）。

## 5. 库存与超卖

| 层级 | 做法 |
|------|------|
| **Redis 预减** | `DECR` / Lua 判断 ≥0；抗读流量，秒杀常用 |
| **DB 扣减** | `UPDATE stock SET num=num-1 WHERE sku_id=? AND num>=1`；以 DB 为准 |
| **预占表** | `available`, `frozen`；下单 frozen+1，支付 confirm，关单 release |
| **乐观锁** | `version` 字段 CAS |
| **悲观锁** | `SELECT ... FOR UPDATE`；热点 SKU 慎用 |

**常规下单**：库存服务内 DB 预占 + 返回成功/失败。  
**秒杀**：Redis 预减 + MQ 异步落单（见 [秒杀.md](./秒杀.md)）。

---

## 6. 缓存策略

| 数据 | 缓存 | 注意 |
|------|------|------|
| 商品详情 | Redis / 本地 Caffeine | 价格以下单时服务端快照为准，不写「以缓存价格下单」 |
| 库存展示 | Redis 缓存可售数 | **展示可略滞后**；扣减以 DB/库存服务为准 |
| submitToken | Redis SET key EX 300 | 一次性消费 |
| 用户地址 | Redis | 下单时仍校验有效性 |
| 订单详情 | 可选缓存 | 写后删；支付状态变更删缓存 |

**缓存一致性**：

- 下单写 DB 后 **删** 订单相关缓存（若存在）。  
- 商品库存：扣减后 **删库存缓存** 或 **异步更新**；接受短暂不一致。  
- 不用「先删缓存再写库」单独解决下单；以 **写 DB + 删缓存** 为主。

**穿透/击穿**：商品 id 布隆过滤；热点 SKU 互斥锁重建缓存。

---

## 7. 读写分离

| 操作 | 路由 |
|------|------|
| 创建订单、更新状态 | **主库** |
| 订单列表、历史订单 | **从库**（可接受秒级延迟） |
| 下单后立即跳转详情 | **读主** 或 客户端轮询带 `forceMaster` |

**主从延迟坑**：支付回调写主库成功，用户刷列表从库未同步 → 显示待支付。  
**解**：支付结果页读主；列表页提示「状态更新中」；或延迟 MQ 推前端。

**分库分表**：按 `user_id` 或 `order_id` 分片；订单号带路由信息（见 [分布式ID.md](./分布式ID.md)）。

## 8. 高并发

| 手段 | 落点 |
|------|------|
| **限流** | 网关 + 用户维度 + 接口 Sentinel |
| **防重** | submitToken、幂等键 |
| **异步** | 非核心逻辑全走 MQ |
| **拆分** | 读商品走缓存；写订单独立连接池 |
| **隔离** | 秒杀与普通下单线程池/集群隔离 |
| **降级** | 券/积分失败是否阻断下单（产品规则） |

**连接池**：订单库连接数按峰值估算；避免一个慢 SQL 拖垮池。

---

## 9. 幂等与防重

| 层级 | 实现 |
|------|------|
| **前端** | 按钮置灰、debounce |
| **submitToken** | 进入结算页生成 token；下单带 token；Redis 删除成功即消费 |
| **业务幂等键** | `client_request_id` / `(user_id, cart_hash)` 唯一索引 |
| **MQ** | 消费端 `order_id` 去重表 |
| **库存** | 预占接口幂等：同一 `order_id` 重复预占返回成功 |

```text
重复请求同一 submitToken → 第二次返回「处理中」或原 orderId
重复 MQ → 消费者查 order 状态已创建则 ack
```

---

## 10. 订单状态机

```text
待支付 → 已支付 → 待发货 → 已发货 → 已完成
   ↓         ↓
 已取消   退款中 → 已退款
```

- **待支付 → 已取消**：超时关单（延迟 MQ / 扫表）+ **释放库存** + 退券。  
- **已支付**：仅支付回调（或查单）可推进；**回调幂等**。  
- 状态变更用 `UPDATE ... WHERE status=?` 乐观推进。

---

## 11. 异常与补偿

| 异常 | 处理 |
|------|------|
| 预占成功，写单失败 | 调库存 **释放**；告警 |
| 写单成功，MQ 失败 | Outbox 重试；不影响用户看到订单 |
| 支付成功，确认库存失败 | 重试 + 人工/对账；订单已支付不能简单关单 |
| 重复支付回调 | 幂等表 + 状态机 |
| 服务宕机 | 预占有超时释放；关单任务扫 **待支付超时** |

---

## 12. 面试追问

| 追问 | 要点 |
|------|------|
| 下单和扣库存哪个先？ | 一般 **先预占库存再写单**；写单失败释放 |
| 要不要 Seata？ | 能预占+本地事务就不用；跨库短事务可 AT |
| 价格变了怎么办？ | 服务端重新算价；与展示价不一致则提示刷新 |
| 购物车合并下单？ | 见 [购物车.md](./购物车.md) |
| 如何压测？ | 限流阈值、DB 行锁热点、MQ 堆积、关单延迟 |

---

## 13. 30 秒收口

「下单同步链路：**submitToken 防重 → 库存预占 → 订单库本地事务写单+券 → 发 MQ 做积分通知**。库存和订单跨服务用 **预占+补偿**，不用长事务 2PC。读商品走缓存，写订单走主库；列表读从库要接受延迟。支付成功后 **确认库存**；超时 **关单释放**。全程 **幂等键 + 状态机**。」
