## 按技术维度速查

| 维度 | 典型场景 |
|------|----------|
| **本地事务** | 单库下单写订单+明细 |
| **分布式事务** | 支付扣款+订单状态；Seata AT/TCC；能不用就不用 |
| **最终一致** | 下单后发 MQ → 积分/通知/搜索索引 |
| **缓存** | 商品详情、库存只读缓存、购物车、Session |
| **读写分离** | 订单列表读从库；写走主库；主从延迟兜底 |
| **高并发** | 秒杀、计数、网关限流、异步化 |
| **幂等** | 下单 token、支付回调、MQ 消费、退款 |
| **对账** | 支付渠道、清结算、差错 |

## 面试怎么选场景答？

1. **先画链路**：用户 → 网关 → 服务 → DB/Cache/MQ。  
2. **标一致性要求**：钱/库存强一致或可补偿；通知/积分最终一致。  
3. **说瓶颈在哪**：DB 行锁、热点 Key、下游 RPC、主从延迟。  
4. **给方案 + 取舍**：为什么不用 2PC、为什么 Redis 预减还要 DB 确认。  
5. **补异常**：重复请求、回调重复、消息重复、宕机恢复。

**30 秒总收口**：  
「互联网场景优先 **业务状态机 + 幂等 + 最终一致**；钱和库存用 **预占/TCC/对账** 兜底；读多写少用 **缓存+读写分离**；峰值用 **限流+异步+削峰**；跨服务少强分布式事务，多用 **本地消息表/MQ**。」
