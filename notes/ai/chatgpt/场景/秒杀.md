# 场景面试：秒杀 / 抢购

> 极短时间超高并发抢有限库存。考察：热点、缓存、MQ 削峰、超卖、限流、与常规下单差异、活动全生命周期。  
> 关联：[下单.md](./下单.md) · [库存扣减.md](./库存扣减.md) · [支付.md](./支付.md) · [限流防刷.md](./限流防刷.md) · [延迟任务.md](./延迟任务.md)

---

## 1. 场景与核心挑战

| 挑战 | 说明 |
|------|------|
| **读洪峰** | 活动页、倒计时、库存查询瞬时 QPS 远超日常 |
| **写热点** | 少数 SKU 行锁/Key 被打穿 |
| **不超卖** | Redis 与 DB 双层闸；最终以 DB 为准可对账 |
| **体验** | 抢不到要快速失败，不能拖垮全站 |
| **隔离** | 秒杀不能拖垮常规下单/支付集群 |
| **作弊** | 脚本、黄牛、一人多号、接口刷量 |

---

## 2. 活动全时间线

```text
【活动前 T-N 天～T-1h】
  配置活动/SKU/配额 → 静态页发布 CDN
  → 库存从 DB 预热进 Redis（可略少留 buffer）
  → 预热商品/规则本地缓存 + Redis
  → 压测、限流阈值、独立集群扩容
  → 答题/验证码开关、黑名单预置

【活动中 开始～结束】
  CDN 静态页 → 网关限流/验证码 → Redis Lua 预减
  → 成功入 MQ → 异步落单/资格 → 引导支付
  → 失败快速返回「已抢光/排队」

【活动后】
  关入口、停写 Redis 库存
  → 消费完 MQ（或按规则丢弃未处理）
  → Redis vs DB 对账校准
  → 超时未付关单释放（见延迟任务）
  → 复盘：超卖、堆积、错误码、渠道支付成功率
```

---

## 3. 架构与隔离

```text
客户端 → CDN(活动页/静态JSON) → 秒杀专用网关/集群
                                      ↓
                              Redis(库存/一人一单)
                                      ↓ 成功
                                   秒杀 MQ
                                      ↓
                              订单/资格落库服务
                                      ↓
                              支付（可复用支付集群，限流）
```

| 隔离点 | 做法 |
|--------|------|
| **集群** | 秒杀独立应用、独立连接池、独立 Redis |
| **库表** | 秒杀订单表/资格表与日常订单分库或分表前缀 |
| **线程池** | 与常规下单线程池隔离，避免互相占满 |
| **入口** | 独立域名/path；活动结束直接 503/静态「已结束」 |

与常规 [下单.md](./下单.md) 差异：**同步不写 MySQL 事务**；先 Redis 再 MQ 再异步落单。

---

## 4. 链路设计（同步极短）

```text
静态化：活动页 CDN + 静态 JSON（开始时间、规则、sku）
         ↓
网关：全局限流 + 用户限流 + 设备指纹/验证码（可选）
         ↓
业务：校验活动窗口、用户资格、一人一单
         ↓
Redis：Lua 原子预减库存 + 记 user 资格
         ↓ 成功
MQ：秒杀请求（userId, skuId, activityId, requestId）
         ↓ 异步
订单服务：写 DB 订单 + DB 库存确认（或仅资格单）
         ↓ 失败
补偿：Redis INCR 回库存 + 删一人一单标记（按规则）
```

**原则**：同步路径越短越好；Redis 挡流量，DB 慢慢落单。

## 5. Redis Lua 示例（库存 + 一人一单）

```lua
-- KEYS[1]=stock:{activity}:{sku}
-- KEYS[2]=sold:{activity}   -- Set of userId
-- ARGV[1]=userId  ARGV[2]=qty(通常1)
local uid = ARGV[1]
local qty = tonumber(ARGV[2])
if redis.call('SISMEMBER', KEYS[2], uid) == 1 then
  return -1   -- 已抢过
end
local stock = tonumber(redis.call('GET', KEYS[1]) or '0')
if stock < qty then
  return 0    -- 库存不足
end
redis.call('DECRBY', KEYS[1], qty)
redis.call('SADD', KEYS[2], uid)
return 1      -- 成功
```

| 返回值 | 含义 | 前端/接口 |
|--------|------|-----------|
| 1 | 抢到资格 | 入队成功，稍后查结果/拉支付 |
| 0 | 售罄 | 快速失败 |
| -1 | 已参与 | 一人一单 |

生产可加 `requestId` 幂等 Set，防重试重复扣。

## 6. 库存三层与对账

| 层 | 作用 |
|----|------|
| **Redis** | 抗并发第一道闸；展示库存也可读此 |
| **MQ** | 削峰填谷；partition key 可用 `skuId` 保同 SKU 顺序 |
| **MySQL** | 最终真相；`WHERE available>=1` 或预占表（见 [库存扣减.md](./库存扣减.md)） |

```text
活动前：DB.available → Redis.stock（可预留 buffer，略少预热）
活动中：以 Redis 为准对外；落单时再扣/确认 DB
活动后：对账 job：Redis 已售 vs DB 已售/订单数
         长款少卖可人工补；短款超卖告警紧急停售+赔付流程
```

---

## 7. 事务 / 分布式事务

| 阶段 | 事务边界 |
|------|----------|
| 同步抢购 | **只操作 Redis**，无跨库事务 |
| 异步落单 | 订单库 **本地事务** 写 order；库存服务本地扣减 |
| 落单失败 | **补偿** Redis INCR + 清一人一单（产品是否允许重试） |
| 支付 | 与常规支付一致：回调幂等 + 库存 confirm（见 [支付.md](./支付.md)） |

**不要**用 Seata 把 Redis + MySQL + MQ 包成全局事务。秒杀本质是 **最终一致 + 可补偿**。

---

## 8. 缓存

| 数据 | 策略 |
|------|------|
| 活动规则/商品文案 | 预热 Redis + 本地 Caffeine；开始前集中加载 |
| 库存展示 | 读 Redis；可接受短暂不准 |
| 用户结果 | Redis `result:{activity}:{user}` 或查询资格表 |
| CDN | HTML/JS/图；动态接口尽量少 |

防击穿：热点 key 永不过期或逻辑过期 + 互斥重建；**禁止**活动开始瞬间大量 key 同时 TTL 归零。

---

## 9. 读写分离

- 活动期：**几乎不读从库做扣减决策**；资格/库存以 Redis/主库写路径为准。  
- 订单结果查询：可 Redis 先查；历史列表读从库。  
- 对账、报表：活动后走从库/离线库。

---

## 10. 高并发与防刷

| 手段 | 说明 |
|------|------|
| CDN + 静态化 | 砍掉 90%+ 读 DB |
| 独立集群 | 资源隔离 |
| 分层限流 | 全局限流 → 用户/IP → SKU 维度 |
| 验证码/答题 | 打散脚本峰值（见 [限流防刷.md](./限流防刷.md)） |
| 排队页 | 令牌桶发「入场券」再允许调抢购接口 |
| 降级 | 关推荐/搜索等非核心；秒杀失败快速返回 |

**一人一单**：Redis Set + DB 唯一索引 `(activity_id, user_id)` 双保险。

---

## 11. 幂等

| 点 | 实现 |
|----|------|
| 抢购请求 | `requestId` / Lua 内 SISMEMBER |
| MQ 消费 | `requestId` 或 `(activity,user)` 去重表 |
| 落单 | 唯一索引防重复订单 |
| 支付 | 同 [支付.md](./支付.md) 回调幂等 |

---

## 12. 异常与补偿

| 异常 | 处理 |
|------|------|
| **Redis 挂** | 降级关秒杀或切「极严限流 + DB」；优先保不超卖 |
| **MQ 堆积** | 扩消费者；活动结束可丢弃未处理（产品：已 Redis 扣的要回滚或人工） |
| 落单失败 | Redis 回库存；告警 |
| 支付超时 | 延迟关单 + 释放 DB/Redis（见 [延迟任务.md](./延迟任务.md)） |
| 超卖（DB 扣失败） | 回滚 Redis、对用户失败提示；对账补洞 |

---

## 13. 面试追问

| 追问 | 要点 |
|------|------|
| Redis 挂了怎么办？ | 关入口或 DB+严格限流；不能裸奔打主库 |
| 消息堆积怎么办？ | 扩容；结束规则明确；已扣 Redis 要补偿策略 |
| 和下单区别？ | 同步不写库、Redis 前置、强隔离、可降级体验 |
| 如何防黄牛？ | 验证码、设备指纹、风控、一人一单、实名 |
| Lua 为啥必要？ | GET+DECR 非原子会超卖；一人一单也要同脚本 |
| 库存预热少一点？ | buffer 防 Redis/DB 不一致导致超卖 |

---

## 14. 30 秒收口

「秒杀同步只做 **限流 + Redis Lua 预减 + 一人一单**，成功丢 **MQ 异步落单**，DB 最终扣减并对账。与常规下单 **集群/库表隔离**。Redis 故障优先关活动保不超卖；堆积扩消费者或按规则回滚。支付、关单走原有状态机，全程幂等。」
