# 场景面试：Feed 流 / 时间线

> 社交/内容 App 首页核心。与 **朋友圈**、**大 V 发通知** 强相关，见专题文档。

---

## 1. 三种模型

| 模式 | 做法 | 适用 | 复杂度 |
|------|------|------|--------|
| **推（写扩散）** | 发帖时写入每个粉丝的 inbox | 粉丝少（<1w）、好友圈 | 写 O(粉丝数) |
| **拉（读扩散）** | 读 Feed 时聚合关注列表最新 post | 粉丝多、大 V | 读 O(关注数) |
| **混合** | 普通用户推；大 V 拉 | **业界主流**（微博/推特/ins） | 读写折中 |

```text
推：发帖重、读 Feed 轻（适合好友 5000 以内，如朋友圈）
拉：发帖轻、读 Feed 重（适合百万粉大 V）
混合：读路径合并 inbox + 大 V timeline
```

## 2. 存储

| 结构 | 说明 |
|------|------|
| **post / moment** | 内容主表 |
| **inbox** | `inbox:{userId}` Redis ZSet 或 DB 表；`(user_id, post_id, ts)` |
| **author_timeline** | 作者发过的 post，个人页 & 大 V 拉取 |
| **follow** | 关注/好友关系 |

冷热：活跃用户体验 inbox 全 Redis；冷用户按需从 DB 重建。

---

## 3. 读路径（混合模式）

```text
1. ZREVRANGE inbox:{me}  → 普通关注源的 post
2. 批量拉 bigV_timeline:{authorId}（我关注的大 V）
3. 多路归并按 ts 排序 → Top N
4. 批量加载 post 详情
5. cursor 分页（ts + id）
```

---

## 4. 写路径（发帖）

```text
同步：写 post + author_timeline
异步 MQ：fan-out 写粉丝 inbox（大 V 跳过，见阈值）
```

---

## 5. 高并发

- Fan-out **MQ 异步**；consumer 水平扩展  
- 大 V **禁止写扩散**  
- 深分页用 **游标**，不用 offset  
- 删帖：MQ 从各 inbox ZREM

---

## 6. 缓存 / 读写分离

- post 详情缓存；写后删  
- inbox 即热数据层  
- 写主；Feed 读 Redis + 从库

---

## 7. 一致性

发帖与 fan-out **最终一致**；用户可接受秒级延迟。

**收口**：「推拉混合；大 V 拉、小号推；inbox+归并；异步 fan-out；游标分页。」
