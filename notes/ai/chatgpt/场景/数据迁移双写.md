# 场景面试：数据迁移 / 双写

---

## 1. 典型场景

- 单库 → 分库分表  
- MySQL → TiDB  
- 机房搬迁

---

## 2. 双写阶段

```text
阶段1：旧库单写，同步程序写新库（追数据）
阶段2：双写（应用写旧+新，或写新回旧）
阶段3：对新库读灰度
阶段4：切写新库，停旧写
阶段5：下线旧库
```

---

## 3. 一致性

- **对账程序**：旧 vs 新 行级比对  
- 以 **update_time / binlog** 追增量  
- 冲突策略：以新为准 / 以旧为准（规则固定）

---

## 4. 事务

- 双写 **无法单事务**；靠对账修复  
- 或 MQ 异步同步（最终一致）

---

## 5. 缓存

- 切读时 **清缓存** 防旧数据  
- 灰度用户 cache key 带版本

---

## 6. 回滚

- 保留旧库只读一段时间  
- 切写失败 → 流量切回

**收口**：「增量同步+双写+对账；灰度切读切写；可回滚。」
