# 场景面试：购物车

---

## 1. 场景

- 加购、改数量、删商品、选中结算  
- 登录前后 **Guest 购物车合并**  
- 大促读多写多，不能拖垮 DB

---

## 2. 存储选型

| 方案 | 适用 |
|------|------|
| **Redis Hash** | `cart:{userId}` field=skuId value=json(qty,checked,ts) |
| **MySQL** | 需持久化、复杂促销试算 |
| **混合** | Redis 热数据 + 异步落库 / 登录合并写 DB |

未登录：`cart:guest:{deviceId}`；登录后 **merge** 到 userId（同 sku 取 max qty 或相加，产品定）。

---

## 3. 事务

- 单用户加购：Redis **HSET** 原子，无跨库事务  
- 合并购物车：Lua 或 单线程 merge + 删 guest key  
- 下单成功后 **删购物车项**（MQ 或下单接口同步删）

---

## 4. 缓存

- 购物车即缓存；注意 **大 Key**（上百 SKU 拆分或分页）  
- TTL：Guest 7 天；登录用户可更长

---

## 5. 读写分离

- 纯 Redis 无读写分离  
- 若落 MySQL：写主，列表读从

---

## 6. 高并发

- 按 userId 分片 Redis  
- 限流：加购接口防刷  
- 结算页 **服务端重新算价**，不信购物车缓存价格

---

## 7. 与下单联动

结算 → 生成 **submitToken** → 下单接口传 sku 列表 → 库存预占 → 清 cart

**收口**：「Redis 存 cart；登录 merge；下单以服务端价为准；下单后删项。」
