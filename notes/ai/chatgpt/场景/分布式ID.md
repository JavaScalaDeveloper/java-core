# 场景面试：分布式 ID / 订单号

---

## 1. 要求

- **全局唯一**、**趋势递增**（利于 B+ 树索引）、高 QPS、可读（可选嵌入时间/机房）

---

## 2. 方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **雪花 Snowflake** | 快、趋势递增 | 时钟回拨；机器 id 管理 |
| **号段** | DB 压力小 | 号段用尽需取新段 |
| **Redis INCR** | 简单 | 单点；持久化依赖 |
| **UUID** | 简单 | 无序、索引差 |

---

## 3. 雪花结构（口述）

```text
1 bit 符号 + 41 bit 时间 + 10 bit 机器 + 12 bit 序列
```

**时钟回拨**：等待 / 借用未来位 / 告警拒绝

---

## 4. 号段模式

```text
UPDATE segment SET max_id=max_id+step WHERE biz=?
  内存发号直到用尽再取
```

双 buffer 平滑切换号段。

---

## 5. 与分库分表

- order_id 含 **user_id 路由** 或 单独映射表  
- 避免跨分片查询

---

## 6. 高并发

- 本地发号（雪花/号段）无 DB 瓶颈  
- Redis INCR 集群

**收口**：「生产常用雪花或号段；要趋势递增；分库带路由信息。」
