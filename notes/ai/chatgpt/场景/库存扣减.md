# 场景面试：库存扣减

> 可售库存的 **查询、预占、确认、释放** 全生命周期。下单/支付/关单/退款都依赖它。

---

## 1. 库存模型

| 字段 | 含义 |
|------|------|
| **available** | 可售 |
| **frozen** | 预占（下单未支付） |
| **sold** | 已售（可选，或由 available+frozen 推导） |

```text
下单预占：available - 1, frozen + 1
支付确认：frozen - 1（sold + 1 若单独字段）
关单释放：frozen - 1, available + 1
退款回滚：available + 1（视是否回可售仓）
```

---

## 2. 扣减 SQL（DB 为准）

```sql
-- 预占
UPDATE stock SET available = available - 1, frozen = frozen + 1
WHERE sku_id = ? AND available >= 1;

-- 确认（幂等：order_id 已 confirm 则直接成功）
UPDATE stock SET frozen = frozen - 1
WHERE sku_id = ? AND frozen >= 1 AND confirm_order_id IS NULL ...;

-- 释放
UPDATE stock SET available = available + 1, frozen = frozen - 1
WHERE sku_id = ? AND frozen >= 1;
```

**乐观锁**：`version` 字段；失败重试有限次数。

---

## 3. Redis 配合

- **展示库存**：缓存 `stock:sku:{id}`  
- **秒杀预减**：Lua 原子  
- **写 DB 后**：删缓存或 DECR 对齐  
- **不一致修复**：定时对账 DB vs Redis

---

## 4. 分布式事务

- 库存单独服务；**单库本地事务** 改 stock 行  
- 与订单：**RPC 预占 + 补偿释放**，不用 2PC  
- 支付 confirm：**幂等 order_id**

---

## 5. 高并发

- 热点 SKU：**行锁竞争** → 拆分库存行（多个 bucket 汇总）或 Redis 前置  
- 批量补货：低峰期操作，避免与大促扣减冲突

---

## 6. 读写分离

- 扣减、预占、释放：**主库**  
- 库存报表、大屏：**从库**（延迟可接受）

---

## 7. 面试收口

「库存用 **available/frozen 两阶段**；DB 条件更新防超卖；Redis 扛读和秒杀；跨订单 **RPC+幂等+补偿**。」
